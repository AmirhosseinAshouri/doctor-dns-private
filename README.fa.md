# doctor dns

*[English](README.md)*

یه سرویس Smart DNS برای ایران که دو بخش داره یه رله داخل کشور و یه سرور خروجی خارج از کشور دامنه های تحریمی میرن سمت رله و از اونجا وصل میشن به خارج بقیه ترافیک هم عادی و مستقیم میره

این فقط یه پروکسی ساده نیست یه سرویس کامله با کنترل دسترسی برای هر کاربر حساب کردن ترافیک سهمیه بندی محدودیت سرعت پنل کاربر و پنل ادمین که همش با یه اسکریپت نصب میشه و جز پکیج های خود دبیان هیچ پیش نیازی نداره

> **نسخه آلفا:** با گزارش باگ هاتون کمک کنید این پروژه رو ببریم جلو

الان این گزارش‌ها از هر چیزی بیشتر ارزش دارن اگه چیزی خراب شد یا سرویسی که انتظار داشتید کار نکرد تو گیت‌هاب [یه ایشو باز کنید](https://github.com/AmirhosseinAshouri/doctor-dns-private/issues) بگید کدوم سمت سرور بوده چی ران کردید و چه اتفاقی افتاده گزارش اینکه یه کنسول نتونسته یه دانلود رو تموم کنه واقعا به درد بخوره بیشتر چیزایی که اینجا هست دقیقا همینجوری یاد گرفته شده

## چه کار میکنه

```
   customer            relay (Iran)              exit (abroad)          service
  ┌────────┐          ┌────────────┐            ┌───────────┐        ┌─────────┐
  │ PS5    │   DNS    │ dnsmasq    │            │           │        │ Sony    │
  │ phone  │ ───────► │  answers   │            │  nginx    │        │ Spotify │
  │ PC     │          │  with self │            │  reads    │        │ …       │
  │        │   TLS    │ nginx      │ ─────────► │  the SNI  │ ─────► │         │
  └────────┘ ───────► │  SNI proxy │            │           │        └─────────┘
                      │ nftables   │            └───────────┘
                      │  gate +    │
                      │  counters  │
                      └────────────┘
```

رله هیچوقت TLS رو باز نمیکنه nginx فقط SNI رو از هندشیک میخونه و یه تونل TCP ساده میزنه به خروجی سرور خروجی هم همین کارو میکنه و وصل میشه به هاست اصلی هیچ چیزی رمزگشایی نمیشه و هیچ سرتیفیکتی به کلاینت نشون داده نمیشه

پورت 80 forward میشه و redirect نمیشه چون سونی و مایکروسافت پکیج های بازی رو روی HTTP ساده از سرورهای Akamai سرو میکنن اگه اونجا پورت 443 رو بزنی یه سرتیفیکت میده که اسم هیچ کنسولی توش نیست

## نصب

یه اسکریپت که یک بار روی هر ماشین ران میشه خودش میپرسه این ماشین کدوم سمته و آدرس اون یکی سرور چیه

این ریپازیتوری خصوصیه، پس سرورها هیچ‌وقت چیزی ازش دانلود نمی‌کنن: روی اون‌ها هیچ راهی به ریپو نیست و لازم هم نیست. `doctor-dns.sh` رو از [ریلیزها](https://github.com/AmirhosseinAshouri/doctor-dns-private/releases) روی کامپیوتر خودتون (با حساب گیت‌هاب واردشده) دانلود کنید و روی هر سرور کپی کنید:

```sh
gh release download -R AmirhosseinAshouri/doctor-dns-private -p doctor-dns.sh
scp doctor-dns.sh root@SERVER:
ssh -t root@SERVER 'bash doctor-dns.sh'
```

این اسکریپت عمدا از روی فایل اجرا میشه نه با پایپ، چون هر کانفیگی که نصب میکنه داخل خود اسکریپت زیر خط exit 0 ذخیره شده پس باید بتونه فایل خودشو بخونه؛ سوال هم میپرسه که پایپ نمیتونه جواب بده. کپی فایل هم روی سرور میمونه که بتونید بخونید، دوباره ران کنید یا باهاش آنینستال کنید. اگه فایل کامل کپی نشده باشه اسکریپت اصلا ران نمیشه

اول **خروجی** رو نصب کنید یه توکن میده که رله ازتون میخواد

ران کردن دوباره‌اش سیفه چون از کانفیگ‌ها بکاپ میگیره و مرحله‌ای که چیزی رو تغییر نمیده کاری هم نمیکنه `sudo bash doctor-dns.sh --uninstall` ماشین رو به حالت اول برمی‌گردونه و فقط کاری رو برمی‌داره که خود این اسکریپت کرده بود

### اپگرید

فایل جدید رو به همون روش کپی کنید و ران کنید — یا بذاریدش توی `/root/doctor-dns.sh` و توی `smartdns-menu` گزینهٔ update رو بزنید؛ قبل از اینکه کاری کنه ورژن خودش رو با ورژن نصب شده روی ماشین چک میکنه، میگه داره برای کدوم سمت اجرا میشه و ازتون میپرسه

```
Version

    installed on this machine:  0.1.0
    this file:                  0.2.0

    this will upgrade this machine from 0.1.0 to 0.2.0.
    your customers, settings, certificates and allowlist are kept.

  go ahead? [y]:
```

ولی حالتی که واقعاً به‌خاطرش وجود دارد آن یکی است: فایل قدیمی‌ای که چند ماه در پوشهٔ خانگی مانده و دوباره اجرا می‌شود. آن وقت می‌گوید این فایل از نصب‌شده قدیمی‌تر است و جواب پیش‌فرض «نه» می‌شود.

دیتاهای کاربرا رمزها سرتیفیکت‌ها و allowlist بیرون از فایل‌هایی هستن که اسکریپت میسازه پس موقع اپگرید حفظ میشن؛ با این حال قبلش یه کپی از دیتابیس در `/var/backups/smart-dns/` گرفته میشه، اون هم با `VACUUM INTO` نه `cp`، چون پنل کنار دیتابیس یک write-ahead log نگه میداره و کپی‌کردن خود فایل میتونه تازه‌ترین ردیف‌ها رو جا بندازه. `--version` نسخهٔ یک فایل رو بدون نصب چیزی چاپ میکنه و `ASSUME_YES=1` جواب پیش‌فرض رو میگیره — برای اپگرید «بله»، برای برگشت به عقب «نه»

### پیشنیازها

دو تا سرور دبیان یا اوبونتو با IP پابلیک برای هرکدوم لازمه:

- **رله** — داخل ایران، همون آدرسی که کاربر DNS خودش رو روش میذاره
- **خروجی** — بیرون، طوری که رله بتونه بهش برسه

نه pip نه npm نه کانتینر. فقط کتابخانه استاندارد پایتون nginx dnsmasq nftables و coturn — همه از ریپوی خود توزیع

### ⚠️انتخاب سرورها و تجربه‌های ما⚠️

سرعت سرویس بیشتر از اینکه به این اسکریپت ربط داشته باشه به مسیر بین سرور ایران و خارج ربط داره؛ فیلترینگ با همه سرورهای خارجی یکسان رفتار نمیکنه، بعضی رو آزاد میذاره بعضی رو کند میکنه و بعضی رو عملا میبنده. نتایج زیر حاصل آزمایش‌های ماست تا هزینه‌تون صرف سروری نشه که کار نمیکنه

| سرور خارج | نتیجه |
|---|---|
| AWS Lightsail آلمان | بدون مشکل کار کرد |
| Hetzner (آلمان و فنلاند) | بدون مشکل و سریع، حدود ۲ مگابایت بر ثانیه |
| Linode فرانکفورت، OVH فرانسه، یک سرور نتلن در ترکیه | به‌خوبی کار کرد |
| DigitalOcean | در هیچ‌یک از ۸ منطقه‌ای که آزمایش شد کار نکرد؛ اتصال برقرار می‌شود، اما پس از چند کیلوبایت دیگر داده‌ای عبور نمی‌کند |
| OVH (برخی آی‌پی‌های جدید) | همان مشکل DigitalOcean |
| Vultr میامی | کار می‌کند، اما بسیار کُند است؛ حدود ۱۰۰ کیلوبایت بر ثانیه |

چند نکته:

- سریع دانلود شدن فایل آزمایشی یک شرکت از داخل ایران تضمین نمی‌کند که سروری که از همان شرکت می‌خرید هم سریع باشد؛ این را در OVH و Vultr به‌وضوح دیدیم.
- یک سرور خارج ممکن است با یک سرور ایران به‌خوبی کار کند و با سرور ایران دیگری نه.
- سرویس روی اینترنت‌های مختلف رفتار یکسانی نداشت: با یک پیکربندی ثابت، روی اینترنت موبایل به‌خوبی کار می‌کرد، اما روی اینترنت خانه بسیار کُند بود. پس سرویس را روی اینترنت‌هایی که مشتریانتان استفاده می‌کنند هم آزمایش کنید.

**پیشنهاد ما:** سرورها رو اول ساعتی بگیرید، روی اینترنت های مختلف تست کنید، اگه اوکی بود تمدید کنید

### پورت‌ها

همه این پورت‌ها رو تو فایروال باز کنید؛ هیچ‌کدومشون رو به پنل ادمین ندید — نصب‌کننده جلوی اونایی که می‌بینه رو می‌گیره ولی قانون فایروالی که خودتون نوشتید رو نمی‌بینه

| | رله (داخل ایران) | خروجی (بیرون) |
|---|---|---|
| **53** udp + tcp | dnsmasq؛ همان آدرسی که مشتری DNS خود را رویش می‌گذارد | — |
| **80** tcp | به بیرون forward می‌شود؛ گواهی هم از همین‌جا اثبات می‌شود | همان |
| **443** tcp | پروکسی SNI | همان |
| **3478** udp | STUN، تا کنسول بتواند نوع NAT خودش را تشخیص دهد | — |
| **8443** tcp | پنل مشتری — فقط روی TLS، پس رلهٔ بدون گواهی اصلاً پنلی سرو نمی‌کند | API همگام‌سازی — فقط به رله‌ها جواب می‌دهد، نه به هیچ‌کس دیگر |
| **8446** tcp | — | فقط روی loopback: مسیر خود خروجی به گوگل روی IPv6، هر جا IPv6 داشته باشد |
| **8444** tcp + udp | فقط اگر تونل داشته باشید: پورت تونل، که فقط به خروجی جواب می‌دهد — تونل *reverse* اینجا گوش می‌دهد | همان، برای تونل *direct* |
| **22** tcp | ssh — هیچ‌وقت پشت دروازه نیست، تا allowlist اشتباه شما را بیرون نیندازد | همان |

پنل ادمین تنها پورتی است که خودتان انتخاب می‌کنید. پیش‌فرضش **9443** است و هر پورت آزادی می‌تواند باشد؛ نصب‌کننده روی 22، 53، 80، 443، 8443، 8446 و پورت تونل جلویتان را می‌گیرد، و `smartdns-access port` بعداً همان قانون را اعمال می‌کند به‌علاوهٔ یک بررسی که چیز دیگری از قبل روی آن پورت گوش نداده باشد.

از بیرون، رله همان ماشینی است که مشتری به آن می‌رسد، پس پورت‌های DNS و پروکسی و STUN و پنلش باید روی اینترنت باز باشند. خروجی فقط از رله و از شما صدا می‌شنود، پس همان 80 و 443 و 8443 و پورت پنل کافی است.

### تونل بین رله و خروجی (اختیاری)

به‌طور پیش‌فرض رله هر اتصال را همان‌طور که هست به خروجی می‌دهد: TCP ساده، و TLS خود مشتری دست‌نخورده داخلش. سریع‌ترین مسیر همین است، ولی اسم هر سایت در مسیر دیده می‌شود، و روی بعضی مسیرها فیلترینگ دقیقاً روی همین کار می‌کند — مثلاً اسم‌های گوگل را می‌کشد و بقیه رد می‌شوند، یا کل یک شرکت را کُند می‌کند.

نصب‌کننده می‌تواند به‌جایش یک تونل [BackPack](https://github.com/AminMGMT/BackPack) — ساختهٔ امین محمدی، بخش [سپاس](#سپاس) را ببینید — روی این مسیر بگذارد. موقع نصب خروجی می‌پرسد — TCP ساده یا BackPack، کدام پروتکل، کدام طرف وصل شود، و کدام پورت — و رله جواب را از توکن جفت‌شدن می‌فهمد، پس دو طرف نمی‌توانند ناهماهنگ تنظیم شوند. مشتری هیچ فرقی حس نمی‌کند: DNS، allowlist، شمارش مصرف، سقف سرعت و هر دو پنل همه قبل از تونل‌اند.

- nginx رله از تونل می‌رود، و فقط وقتی تونل پایین است مستقیم به خروجی.
- BackPack موقع نصب از ریلیزهای خودش دانلود و با hash‌ای که داخل نصب‌کننده ثابت شده چک می‌شود. جزو این پروژه نیست (مجوزش AGPL-3.0 است). سرور بدون اینترنت: `BACKPACK_TARBALL=/path/to/the.tar.gz`.
- پورت طرفی که گوش می‌دهد فقط به ماشین مقابل جواب می‌دهد.
- برگشت به TCP ساده با یک دستور، روی هر کدام از دو ماشین: `sudo smartdns-tunnel off`. برای عوض کردن پروتکل، پورت یا طرفی که وصل می‌شود: `sudo bash doctor-dns.sh --tunnel` اول روی خروجی، بعد روی رله. `smartdns-logs` لاگش را نشان می‌دهد و `smartdns-restart` ری‌استارتش می‌کند.

اینکه کدام پروتکل به یک مسیر می‌خورد به خود مسیر بستگی دارد، پس یکی دو تا را امتحان کنید: با `--tunnel` عوض کردنش یک خط است. **stealth** رمزدار است و شبیه بایت‌های تصادفی، و پیش‌فرض هم همین است؛ **wss** و **wssmux** شبیه یک سایت HTTPS معمولی‌اند؛ **tcp** و **ws** و نسخه‌های mux آن‌ها رمز ندارند، پس اسم سایت‌ها همچنان دیده می‌شود. در تست خود ما **quic** و **udp** اصلاً وصل نشدند. تونل *direct*، که رله به خروجی وصل می‌شود، چهار پروتکل دارد: stealth، wss، tcp و ws.

### چند سرور خروجی (اختیاری)

رله می‌تونه مشتری‌هاش رو از بیشتر از یه خروجی بفرسته. خروجی‌ای که اول نصب می‌کنید اصلی می‌مونه — دیتابیس، پنل مدیریت و ربات روی اونه. بقیه *خروجی اضافه* هستن: سرورهایی در خارج که فقط ترافیک رد می‌کنن.

1. اول رله رو به این نسخه آپگرید کنید: باید خروجی خودش رو بشناسه تا در صورت مشکل به اون برگرده.
2. روی سرور تازه نصب‌کننده رو اجرا کنید و **3) extra exit** رو بزنید. آی‌پی رله رو بدید — چندتا رله، با کاما جدا. nginx طوری تنظیم میشه که فقط همون رله‌ها وصل بشن و هیچ‌کس دیگه: نه پنل، نه ربات، نه دیتابیس دوم.
3. توی ربات، **🛠 مدیریت ← 🌍 خروجی‌ها ← ➕**، با اسم و آی‌پی اضافه‌اش کنید.

تا یک دقیقه رله اون رو می‌شناسه و تا پنج دقیقه اندازه‌اش می‌گیره. رله هر پنج دقیقه زمان وصل شدن به هر خروجی رو اندازه می‌گیره — همون مسیری که به هر اتصال مشتری اضافه میشه — و مشتری‌ها توی ربات **🌍 سرور خروجی** رو می‌بینن: خروجی‌ها به ترتیب همین پینگ، و **⚡️ خودکار** که پیش‌فرضه و همیشه سریع‌ترین رو انتخاب میکنه. انتخابشون به‌صورت یه map روی آی‌پیشون به nginx می‌رسه، که فقط وقتی عوض بشه و فقط بعد از قبول `nginx -t` بازنویسی میشه. اگه یه خروجی اضافه جواب نده، nginx مشتری‌هاش رو تا برگشتنش به خروجی اصلی می‌فرسته.

**تونل برای خروجی اضافه.** هر خروجی اضافه می‌تونه تونل خودش رو داشته باشه. نصب‌کننده‌اش می‌پرسه — ترنسپورت و پورت؛ همیشه رله شماره‌گیری می‌کنه — و آخرش یه خط چاپ میکنه:

```
یه اسم | 203.0.113.10 | bp-stealth-8444-d.<token>
```

اون خط رو موقع اضافه کردن خروجی توی ربات بذارید، یا بعداً از دکمهٔ **🔀 تونل** همون خروجی؛ برای برگشتن به TCP ساده همون‌جا «حذف» بفرستید. اون‌وقت رله برای هر خروجیِ تونل‌دار یه کلاینت BackPack اجرا میکنه و nginx مشتری‌های اون خروجی رو به سر تونل می‌فرسته؛ اگه تونل نبود مستقیم به همون خروجی، و فقط بعدش به خروجی اصلی.

رله برای این کار به BackPack نیاز داره. اگه تا حالا هیچ تونلی نداشته، یه بار روی رله doctor-dns.sh رو با `--tunnel` اجرا کنید؛ تا اون موقع رله مستقیم وصل میشه و توی `smartdns-logs` هم میگه.

تونل خود جفت (رله و خروجی اصلی) هیچ فرقی نکرده و تنظیماتش با همون توکن پیرینگ منتقل میشه.

#### خروجی بعدی رو کجا بگیریم

صفحهٔ **مانیتورینگ** توی پنل مدیریت همین تصمیمه، یکجا:

* **مشتری‌های فعال** — هر آی‌پی که همین حالا وصله، رفت‌وبرگشت از دستگاهش تا رله، تعداد اتصال‌های بازش، خروجی‌ای که ازش رد میشه، مسیر رله تا اون خروجی، و جمع این دو. عدد اول از خود کرنل رله (`ss -ti`) و روی اتصال‌هایی که مشتری از قبل باز کرده خونده میشه، پس اندازه‌گیریش هیچ هزینه‌ای نداره و هیچ‌جا پینگ نمی‌زنه.
* **خروجی‌ها** — هر کدوم با آخرین پینگی که رله گرفته و تعداد مشتری‌هایی که روش هستن.
* **سرورهای بازی‌ها کجا هستن** — هر دامنهٔ بازی از روی خروجی resolve میشه و کشور آی‌پیش پرسیده میشه؛ بعد به تفکیک کشور، با اسم بازی‌های هر کشور. کشوری که تعداد زیادی ازشون اونجاست، همون جاییه که خروجی بعدی ارزش داره: از اونجا ترافیک لاگین و فروشگاه و دانلود راه کوتاه‌تری داره.

این پینگ داخل بازی نیست و هیچ‌جای پنل هم چنین چیزی نمی‌گه. ترافیک خود مسابقه هیچ‌وقت از سرویس رد نمیشه — فقط فروشگاه و لاگین و دانلود — پس این اعداد دقیقاً همون مسیری رو توصیف می‌کنن که سرویس حمل می‌کنه. کشور هر آی‌پی یک‌بار پرسیده و یک روز نگه داشته میشه؛ کل فهرست توی چند ساعت و در پس‌زمینه پر میشه.

### کنترل دسترسی

یک رلهٔ تازه به همه جواب می‌دهد. این تصمیم کسی نیست؛ واقعیت این است که رله قبل از ثبت اولین آی‌پی نصب می‌شود و بستنِ آن روی یک allowlist خالی یعنی قطع‌کردن همهٔ کاربرها یکجا — از جمله خود اپراتور.

رله تازه نصب‌شده به همه جواب میده، ولی بعد از اولین سینک و ثبت IP خودشو می‌بنده و فقط به IPهای ثبت‌شده سرویس میده پورت SSH هیچ‌وقت بسته نمیشه پس نگران نباشید که دسترسیتون قطع بشه

```sh
smartdns-acl enforce status   # الان کدام حالت است
smartdns-acl enforce off      # باز بماند، و بستن خودکار لغو شود
```

با `ENFORCE=no` روی خط فرمان نصب، از همان اول انصراف می‌دهید.

## بعد از نصب

هر طرف در پایان نصب می‌گوید چه چیزی راه انداخته: رله آدرس DNS و پنل مشتری را می‌گوید، خروجی پنل اپراتور و رمزش را — رمز فقط همان یک بار نشان داده می‌شود.

پنل اپراتور تمام رابط مدیریتی است: مشتری‌ها، سهمیه و سرعتشان، قالب‌های سرویس، فهرست دامنه‌ها، مانیتورینگ زندهٔ اینکه چه کسی وصل است و سرورهای بازی‌ها کجا هستند، پایش سرورها، رسیدهای پرداخت، و بکاپ و بازگردانی. چیزهای زیر برای مواردی هستند که یک صفحهٔ وب نمی‌تواند حلشان کند: خواندن وضعیت از روی ssh، و برگشتن به پنلی که دیگر به آن نمی‌رسید.

### روی خروجی

**`smartdns-access`** — پنل ادمین کجاست و چطور عوضش کنید. بدون آرگومان که اجرا شود، آدرس کامل را چاپ می‌کند؛ از همان کانفیگی می‌خواند که پنل واقعاً با آن سرو می‌شود.

```sh
smartdns-access                  # آدرسی که جواب می‌دهد — یادتان رفته؟ از اینجا
smartdns-access port 9443        # جابه‌جایی، اگر فایروال سر راه است
smartdns-access path [new]       # مسیر مخفی را عوض یا از نو قرعه بکش
smartdns-access password [new]   # رمز تازه؛ رمز قبلی بازیابی‌شدنی نیست
smartdns-access rotate           # مسیر تازه و رمز تازه، با هم
```

از این سه تا، فقط **رمز** واقعاً احراز هویت است. پورت فقط پنل را از سر راه اسکن اتفاقی کنار می‌برد و بس؛ مسیر هرچند حدس‌نزدنی است، در هر درخواست سفر می‌کند و در لاگ هر پروکسی سر راه می‌نشیند. رمز هیچ‌وقت ذخیره نمی‌شود — فقط هَش نمکی‌اش — و برای همین رمز فراموش‌شده جایگزین می‌شود، نه بازیابی.

### روی رله

**`smartdns`** — فهرست دامنه‌هایی که از رله رد می‌شوند.

```sh
smartdns status                  # این ماشین دارد چه کار می‌کند
smartdns list                    # هر دامنه‌ای که مسیریابی می‌شود
smartdns find spotify            # کدام‌ها می‌خورند
smartdns add example.com         # یکی دیگر را هم از رله ببر
smartdns del example.com         # دیگر نبر
smartdns bypass api.example.com  # این یکی هیچ‌وقت از رله نرود، حتی با اینکه
                                 # والدش می‌رود — برای سرویس‌هایی که اصلاً
                                 # روی ۴۴۳ نیستند
smartdns test example.com        # این رله برایش چه جواب می‌دهد
```

**`smartdns-rules`** — هر قالب با یک دامنه چه می‌کند، پرسیده از خود resolverها. هر قالبی که مشتری دارد resolver خودش را روی رله می‌گیرد؛ قالب پیش‌فرض همان resolver روی پورت ۵۳ است.

```sh
smartdns-rules                   # همهٔ قالب‌ها: پورت، مشتری‌ها، و اینکه چند
                                 # دامنه را redirect، bypass و pin می‌کنند
smartdns-rules show test         # فهرست کامل یک قالب
smartdns-rules check gemini.google.com
                                 # قانون هر قالب برای آن، و جوابی که resolverش
                                 # واقعاً می‌دهد - اگر نخوانند، هشدار می‌دهد
```

**`smartdns-watch`** — دستگاه یک مشتری همین الان چه دامنه‌هایی را می‌پرسد، و این رله هر کدام را به کجا فرستاد. برای پیدا کردن اینکه یک سرویس چه دامنه‌هایی لازم دارد: مشتری سرویس را باز کند تا خطا بدهد، و شما نگاه کنید.

```sh
sudo smartdns-watch ali          # یک مشتری - با نام کاربری، با برچسبی که
                                 # smartdns-acl list نشان می‌دهد (u12)، یا با آی‌پی
sudo smartdns-watch              # همه، هر خط با اسم کسی که پرسیده
```

`via relay` یعنی همین حالا از رله می‌رود. `direct` یعنی از کنار رله رفته: اگر سرویس ایران را قبول نمی‌کند، همین دامنه‌ها را اضافه کنید، با `smartdns add` یا بخش «دامنه‌ها» در پنل. `filtered in Iran` یعنی فیلتر خود ایران است که با هیچ مسیری رد نمی‌شود، و `no answer` معمولاً یعنی آن آی‌پی ثبت نشده. فقط دامنه‌هایی را اضافه کنید که سرویس با HTTPS یا HTTP ساده از آن‌ها استفاده می‌کند - سرورهای خود بازی روی پورت‌های دیگرند و مسیردادنشان بازی را خراب می‌کند. هیچ چیزی ذخیره نمی‌شود: همان چیزی که چاپ می‌کند همه‌اش است.

#### اضافه کردن یک بازی یا برنامه

سرویسی که ایران را قبول نمی‌کند و هنوز در لیست نیست: رله می‌تواند نشانتان بدهد چه لازم دارد.

۱. آی‌پی دستگاهی که با آن تست می‌کنید را مثل همیشه ثبت کنید، بعد روی رله با نام کاربری نگاهش کنید:

```sh
sudo smartdns-watch ali
```

۲. بازی یا برنامه را روی همان دستگاه باز کنید تا خطایش را نشان بدهد.

۳. اسم‌هایی که رد می‌شوند را بخوانید. آن‌هایی که `direct` دارند از کنار رله رفته‌اند؛ اسم‌های خود سرویس بینشان - نه تبلیغ و آمار - همان‌هایی‌اند که باید مسیر بگیرند. اسمی که جوابش آدرسی است که به جایی نمی‌رسد، مثل `direct 0.0.0.1`، یعنی خود سرویس در DNSش ایران را رد کرده: آن را هم اضافه کنید.

۴. اضافه‌شان کنید، از بخش «دامنه‌ها» در پنل (و بعد در قالبی که مشتری رویش است تیکشان بزنید)، یا روی رله:

```sh
sudo smartdns add example.com
```

۵. دوباره بازش کنید. حالا جلوی آن اسم‌ها باید `via relay` بیاید.

اگر سرویس بعد از اضافه شدن یک اسم از کار افتاد، آن اسم روی پورتی استفاده می‌شود که رله جابه‌جا نمی‌کند - سرورهای خود بازی معمولاً این‌طورند. برش دارید:

```sh
sudo smartdns del example.com
```

کاری که از این راه نمی‌شود کرد: اسم‌هایی که سرویس خودش پیدا می‌کند و از DNS نمی‌پرسد - بعضی بازی‌های موبایل این‌طورند و در `smartdns-watch` هیچ چیزی از آن‌ها دیده نمی‌شود - ترافیکی که نه HTTPS است نه HTTP ساده، و اسم‌هایی که `filtered in Iran` هستند. وقتی مجموعه‌ای از اسم‌ها جواب داد، [یک issue باز کنید](https://github.com/AmirhosseinAshouri/doctor-dns-private/issues) و بنویسیدشان تا به لیست پیش‌فرض اضافه شوند.

**`smartdns-acl`** — چه کسی اجازهٔ استفاده از رله را دارد و چقدر مصرف کرده. پنل به‌جای دست‌زدن مستقیم به nftables همین را صدا می‌زند، تا قانونِ اینکه چه چیزی مجاز است یک جا بیشتر نباشد.

```sh
smartdns-acl list                # همه، با مصرفشان
smartdns-acl usage 5.188.44.19   # یک آدرس
smartdns-acl add 5.188.44.19 ali # دستی ثبت کن
smartdns-acl del 5.188.44.19
smartdns-acl reset <ip>|--all    # صفر کردن شمارنده‌ها
smartdns-acl enforce status      # باز است یا فقط آدرس‌های ثبت‌شده؟
smartdns-acl enforce on          # ببند
smartdns-acl enforce off         # برای همه باز کن
smartdns-acl save                # همین حالا روی دیسک ذخیره کن
```

`enforce on` وقتی هیچ‌کس ثبت نشده باشد امتناع می‌کند — بستن یک رلهٔ زنده روی لیست خالی یعنی قطع‌کردن همهٔ مشتری‌ها یکجا، و این اشتباهی است که از آن‌طرفِ یک اتصال قطع‌شده برگشت‌ناپذیر به نظر می‌رسد. اگر واقعاً منظورتان همان است، `--allow-empty` را اضافه کنید. `--json` روی `list` و `usage` خروجی‌ای می‌دهد که برای برنامه است نه آدم.

**`smartdns-shape`** — سقف دانلود به‌ازای هر مشتری، با htb + fq_codel.

```sh
smartdns-shape list              # چه چیزی الان اعمال است
smartdns-shape off               # همهٔ محدودیت‌ها را بردار
```

عامل همگام‌سازی این‌ها را هر سی ثانیه از پنل می‌گیرد و اعمال می‌کند، پس سرعت را آنجا تنظیم کنید نه اینجا.

### روی هر دو

**`smartdns-logs`** — این ماشین چه کرده، همهٔ بخش‌هایش با هم. خودش تشخیص می‌دهد رله است یا خروجی.

```sh
sudo smartdns-logs               # هر بخش: روشن است یا نه، و ۱۰۰ خط آخرش
sudo smartdns-logs -e            # فقط هشدارها و خطاها
sudo smartdns-logs -f            # دنبال‌کردن زنده؛ ‎-e -f‎ فقط برای مشکل‌ها
sudo smartdns-logs -n 500        # خطوط بیشتر برای هر بخش
sudo smartdns-logs --report      # همه‌اش در یک فایل برای فرستادن، رمزها پوشانده
```

پنل‌ها برای هر درخواست و هر کار اپراتور یک خط می‌نویسند، و رله هر دامنه‌ای را که در هر قالب مسیرش عوض شود و هر مشتری‌ای را که بین قالب‌ها جابه‌جا شود ثبت می‌کند. هشدارها و خطاها سطح syslog دارند و `-e` همان را می‌خواند. رمز، نشست و توکن هیچ‌وقت نوشته نمی‌شوند. خروجی معمولی برای صفحهٔ خودتان است — خط شروع پنل ادمین آدرسش را دارد. `--report` هر رمزی را که در کانفیگ ماشین هست، هر جا پیدا شود، می‌پوشاند و آن آدرس هم جزوش است؛ ولی آی‌پی و یوزرنیم مشتری‌ها در آن می‌ماند، پس فقط برای کسی بفرستید که به او اعتماد دارید.

**`smartdns-restart`** — همهٔ بخش‌های این ماشین را با هم ری‌استارت می‌کند و بعد نشان می‌دهد کدام‌ها دوباره بالا آمدند. خودش تشخیص می‌دهد رله است یا خروجی.

```sh
sudo smartdns-restart
```

روی رله، اتصال‌های باز مشتری‌ها یک لحظه قطع می‌شوند و بلافاصله برمی‌گردند. اگر کانفیگ nginx یا dnsmasq خطا داشته باشد، آن بخش ری‌استارت نمی‌شود و با همان حالت قبلی روشن می‌ماند، و دستور دلیلش را می‌گوید. nftables هیچ‌وقت ری‌استارت نمی‌شود، چون لیست آدرس‌های مجاز و مصرفی را که از آخرین ذخیره شمرده شده از بین می‌برد.

**`smartdns-tunnel`** — تونل بین رله و خروجی، اگر باشد: دیدنش، خاموش کردنش، روشن کردنش.

```sh
sudo smartdns-tunnel             # چیست، و آیا ترافیک از آن رد می‌شود
sudo smartdns-tunnel off         # برگشت به TCP ساده، همین الان
sudo smartdns-tunnel on          # دوباره روشن، با همان تنظیمات قبلی
sudo bash doctor-dns.sh --tunnel # عوض کردنش - اول روی خروجی، بعد روی رله
```

برای `off` هر کدام از دو ماشین کافی است: nginx رله به‌محض اینکه سر تونل روی آن جواب ندهد، مستقیم به خروجی می‌رود، فرقی نمی‌کند کدام ماشین خاموشش کرده باشد. انتخاب ذخیره می‌شود، پس ارتقا تونل را دوباره روشن نمی‌کند. `--tunnel` سؤال‌های تونل را روی ماشینی که از قبل نصب شده دوباره می‌پرسد: روی خروجی با تنظیمات فعلی به‌عنوان جواب‌هایی که با Enter انتخاب می‌شوند، و روی رله توکن جفت‌شدن تازه‌ای را می‌خواهد که خروجی چاپ کرده.

**`smartdns-menu`** — همهٔ دستورهای این صفحه در یک منو، برای وقتی که اسم دستوری که می‌خواهید یادتان نیست. هر گزینه قبل از اجرا دستورش را نشان می‌دهد، تا دفعهٔ بعد خودتان تایپش کنید.

```sh
sudo smartdns-menu
```

```sh
smartdns-cert panel.example.com  # گواهی برای آن نام بگیر یا تمدید کن
sudo bash doctor-dns.sh --version
sudo bash doctor-dns.sh --uninstall
```

`smartdns-cert` برای بیست ثانیه‌ای که چالش طول می‌کشد پورت ۸۰ را قرض می‌گیرد، پس دانلود کنسول از روی رله همان‌قدر گیر می‌کند و بعد ادامه می‌دهد. یک تایمر خودش تمدید می‌کند، از وقتی چیزی برای تمدید باشد.

## ربات تلگرام

هر کاری که مشتری توی صفحهٔ رله انجام میده، توی ربات تلگرام هم می‌تونه — به‌علاوهٔ خرید پلن، که از صفحهٔ وب نمیشه. اپراتور هم سرویس رو از همون ربات مدیریت میکنه.

ربات روی سرور خروجی به اسم `smartdns-bot` اجرا میشه، چون تلگرام داخل ایران فیلتره. با نصب خروجی نصب میشه و تا توکن نگیره کاری نمیکنه. هیچ پورتی باز نمیکنه؛ فقط خودش به تلگرام وصل میشه.

### راه‌اندازی

1. توی تلگرام با [@BotFather](https://t.me/BotFather) یه ربات بسازید و توکنش رو کپی کنید.
2. توی پنل مدیریت، **تنظیمات ← ربات تلگرام**، توکن رو بذارید. ربات چند ثانیه بعد وصل میشه.
3. همون‌جا یه کد یک‌بارمصرف نشون داده میشه. `/admin کد` رو به ربات بفرستید تا مدیرش بشید؛ دکمهٔ **🛠 مدیریت** به منوش اضافه میشه. هر کد فقط یه بار و تا ۲۴ ساعت کار میکنه؛ برای هر مدیر تازه، کد تازه بگیرید.
4. توی ربات، از **🛠 مدیریت** پلن‌ها رو بسازید و شمارهٔ کارت، مرچنت زیبال یا هر دو رو تنظیم کنید.

یا از ssh:

```sh
sudo smartdns-bot token          # توکن رو می‌پرسه و کد مدیریت رو چاپ میکنه
sudo smartdns-bot code           # کد مدیریت تازه
sudo smartdns-bot status         # توکن، اسم ربات، مدیرها، رله‌ای که بهش لینک میده
sudo smartdns-bot off            # پاک کردن توکن
```

### مشتری چه کار می‌تونه بکنه

- **`/start`** یه حساب باز میکنه — در انتظار و خالی، مثل ثبت‌نام وب.
- **🎁 تست رایگان**: یه تست ۲۴ ساعته، برای هر حساب تلگرام فقط یک بار، تا وقتی هیچ پلنی نگرفته باشه.
- **👤 حساب من**: وضعیت، پلن، آی‌پی ثبت‌شده، مصرف، حجم، سرعت و تاریخ پایان.
- **🛒 خرید / تمدید**: انتخاب پلن و پرداخت کارت‌به‌کارت (با فرستادن عکس رسید) یا آنلاین با زیبال.
- **🌐 ثبت آی‌پی**: یه مینی‌اپ که آی‌پی اینترنت گوشی رو ثبت میکنه، یا نوشتن دستی آی‌پی.
- **📡 آدرس DNS**: آدرسی که باید توی کنسول، گوشی یا مودم گذاشت.
- **📶 پینگ بازی‌ها**: پینگ هر بازی از سرور ایران، همین الان — سبز، زرد یا قرمز، سریع‌ترها اول.
- **🌍 سرور خروجی**: انتخاب خروجی بر اساس پینگش از رله، یا گذاشتن روی خودکار — وقتی بیشتر از یه خروجی باشه نشون داده میشه.

ربات خودش پیام میده: در ۸۰٪ و ۹۵٪ حجم، وقتی حجم یا دوره تموم میشه، وقتی رسید تأیید یا رد میشه، و وقتی حساب فعال میشه.

**تست رایگان.** به حساب تازه یه تست پیشنهاد میشه — به‌صورت پیش‌فرض ۱ گیگ برای ۲۴ ساعت — که سرویس رو همون لحظه روشن میکنه تا مشتری قبل از پرداخت امتحانش کنه. فقط تا وقتی پیشنهاد میشه که حساب هیچ‌وقت چیزی نداشته باشه: بعد از تموم شدن تست یا خرید پلن، دیگه پیشنهاد نمیشه. گرفتنش روی حساب ثبت میشه تا دوبار گرفته نشه، و توی آمار ربات هم دیده میشه. حجم، مدت و سرعتش رو از **🛠 مدیریت ← 🎁 تست رایگان** تنظیم کنید یا همون‌جا خاموشش کنید.

خرید یعنی تمدید: حجم میشه حجم پلن، مصرف از صفر شروع میشه و دوره از همون روز حساب میشه. پلن می‌تونه یه قالب هم داشته باشه که حساب به اون منتقل میشه.

**پینگ بازی‌ها.** رله هر پنج دقیقه زمان وصل شدن به چندتا از دامنه‌های هر بازی رو اندازه می‌گیره — همون‌هایی که توی لیست DNS خودش هستن — و ربات نتیجه رو نشون میده: مشتری برای هر بازی یه خط می‌بینه، مدیر هر هاست، آی‌پیش، درصد از دست رفتن و اینکه کدوم رله اندازه گرفته. هیچ اندازه‌گیری‌ای از راه خروجی‌ها انجام نمیشه: خروجی‌ها ترافیک مشتری رو می‌برن و به همون کار سپرده میشن.

این پینگِ سرور ایرانه، نه مشتری: ترافیک خود بازی آنلاین مستقیم از اینترنت مشتری به سرور بازی میره، نه از رله. با این حال بهترین راهنماست که کدوم بازی‌ها از ایران خوب جواب میدن و کدوم‌ها رو ایران کلا فیلتر کرده. زمان وصل شدن TCP اندازه گرفته میشه نه پینگ ICMP، چون خیلی از سرورهای بازی به پینگ جواب نمیدن؛ اسم‌ها هم از DNSهای عمومی پرسیده میشن، نه DNS خود رله.

### اپراتور چه کار می‌تونه بکنه

توی **🛠 مدیریت**:

- **رسیدها**: هر رسید تازه با عکسش و دکمه‌های تأیید و رد میاد. تأیید، پلنی رو که رسید براش فرستاده شده اعمال میکنه. رسیدی که توی پنل مدیریت تأیید بشه هم پلنش اعمال میشه.
- **کاربران**: پیدا کردن با اسم، شناسه، آیدی تلگرام یا آی‌پی؛ تنظیم حجم، روز و سرعت، اعمال پلن، عوض کردن قالب، صفر کردن مصرف، مسدود کردن.
- **پلن‌ها**: ساختن، ویرایش، توقف فروش، حذف.
- **تست رایگان**: حجم، مدت و سرعتش، یا خاموش کردنش؛ و اینکه چند نفر گرفتنش.
- **روش‌های پرداخت**: شمارهٔ کارت و اسم صاحبش، مرچنت زیبال.
- **آمار**: کاربرها بر اساس وضعیت، رسیدهای در انتظار، فروش ۳۰ روز اخیر و سلامت هر سرور.
- **پینگ**: هاست‌های هر بازی همون‌طور که رله آخرین بار اندازه گرفته: آی‌پی، زمان، از دست رفتن، و اینکه کدوم‌ها رو ایران فیلتر کرده.
- **خروجی‌ها**: اضافه کردن، تغییر نام، غیرفعال کردن یا حذف خروجی‌های اضافه، و دیدن پینگ هر کدوم و اینکه چند نفر انتخابش کردن.
- **پیام همگانی**: یه پیام به همهٔ کسایی که ربات رو استارت کردن، بعد از پیش‌نمایش.

### مینی‌اپ و پرداخت آنلاین

هر دو صفحه‌هایی روی رله هستن، چون هر کدوم چیزی لازم داره که فقط رله داره: آی‌پی واقعی مشتری، و یه سرور ایرانی که زیبال جوابش رو بده و مشتری رو بهش برگردونه. پس هر دو لازم دارن رله دامنه و سرتیفیکت داشته باشه — مثل پنل کاربرش. رله توی هر همگام‌سازی آدرس صفحه‌هاش رو به خروجی میگه؛ تا وقتی رله‌ای با دامنه همگام نشده، ربات فقط نوشتن دستی آی‌پی و کارت‌به‌کارت رو پیشنهاد میده.

- **مینی‌اپ** همون آی‌پی‌ای رو می‌بینه که گوشی باهاش وصله. اگه فیلترشکن روشن باشه، آی‌پی فیلترشکن دیده میشه — صفحه میگه اول خاموشش کنید.
- **زیبال** باید آدرس بازگشت رله رو قبول کنه: دامنهٔ رله رو، که ربات توی روش‌های پرداخت نشون میده، توی پنل زیبال به‌عنوان وب‌سایتتون ثبت کنید. پرداخت قبل از ثبت شدن، از روی رله با خود زیبال تأیید میشه، فقط برای همون سفارشی که براش شروع شده، و فقط اگه مبلغش کامل پرداخت شده باشه. قیمت‌ها به تومانه؛ از زیبال همون مبلغ به ریال خواسته میشه.

### ظاهرش

پنل‌ها و ربات با هویت **Fasty DNS** طراحی شدن: مشکیِ `#07080A`، سبزِ سیگنال `#C7F000`، خط‌های یک‌پیکسلی `#23272E`، بدون گوشهٔ گرد و بدون سایه — عمق از اختلاف سطح و خط میاد. متن با Space Grotesk و هر عدد، آدرس و واحد با JetBrains Mono، که سخت‌گیرانه‌ترین قانون این سیستمه.

هر دو فونت **داخل خود `doctor-dns.sh`** حمل میشن و پنل‌ها خودشون از `/usr/local/share/smart-dns/fonts` سروشون می‌کنن. گوگل‌فونت توی ایران فیلتره و صفحه‌ای که نتونه فونتش رو بگیره، با هر فونتی که روی دستگاه هست کشیده میشه. این فایل‌ها فقط حروف لاتین و اعداد رو دارن — روی هم حدود ۵۰ کیلوبایت از نصب‌کننده — و متن فارسی با فونت خود دستگاه نوشته میشه.

لوگو به‌صورت SVG داخل صفحه کشیده میشه، نه دانلود: نه درخواستی می‌خواد نه گم میشه. `assets/fonts/` دو فونت رو به‌صورت base64 نگه میداره.

## نحوه بیلد پروژه

فایل doctor-dns.sh دستی نوشته نمیشه و جنریت میشه؛ همه‌چیز تو `templates/`، `common/` و `domains/` هست، `tools/installer-logic.sh` منطق اسکریپته و `tools/build-installer.py` این‌ها رو به هم می‌دوزه:

```sh
python3 tools/build-installer.py   # doctor-dns.sh را بازنویسی می‌کند
bash -n doctor-dns.sh              # همچنان بشِ معتبر می‌ماند
python3 tools/test-websignup.py    # …و همین‌طور بقیهٔ تست‌ها
```

payloadها زیر `exit 0` می‌نشینند و هر خطشان با `#` شروع می‌شود؛ همین است که کل فایل را بشِ معتبر نگه می‌دارد — پس `bash -n` واقعاً چیزی را بررسی می‌کند، و هر کسی می‌تواند قبل از اجرا با root، تک‌تک کانفیگ‌هایی را که قرار است اجرا شوند بخواند.

## ساختار پیاده سازی

یه دیتابیس به همه رله‌ها سرویس میده تا سهمیه کاربر تو کل سیستم یکسان باشه نه به‌ازای هر ماشین

```
  exit node                          relay(s)
  ┌──────────────────────┐          ┌──────────────────────┐
  │ smartdns-panel       │ ◄─────── │ smartdns-sync        │
  │  sqlite + sync API   │   30s    │  usage up,           │
  │                      │ ───────► │  allowlist down      │
  │ smartdns-admin       │          │                      │
  │  operator's panel    │          │ customer's panel     │
  └──────────────────────┘          └──────────────────────┘
```

همیشه رله است که تماس رو برقرار میکنه؛ رله تو وضعیت شبکه‌ای سخت‌تری هست و این‌طوری به هیچ پورت ورودی تازه‌ای نیاز نداره

پنل کاربر روی رله قرار داره چون باید بتونه IP واقعی کاربر رو ببینه و ثبت کنه

## محدودیت ها

- **آپلود شکل داده نمیشه.** فقط جهت دانلود سقف داره؛ محدودکردن ورودی به یک دستگاه ifb نیاز داره و به‌جای صف، بسته دور می‌ریزه — برای سرویسی که ترافیکش غالبا ورودیه.
- **رله بدون سرتیفیکت پنل کاربر نداره.** اون صفحه رمز می‌پرسه، و اینجا هیچ‌چیز روی HTTP ساده رمز نمی‌پرسه — پس اصلا سرو نمیشه، نه اینکه ناامن سرو بشه. روی چنین رله‌ای کسی نمی‌تونه ثبت‌نام کنه یا IP ثبت کنه، تا وقتی دامنه‌ای بهش بدید.
- **صفحهٔ وب تست رایگان نداره.** ثبت‌نام اونجا یه حساب میده و جایی برای فرستادن رسید — نه ترافیک — تا وقتی پلنی خریده بشه یا اپراتور پلن بذاره. تست رایگان فقط توی ربات تلگرام هست.
- **تست برای هر حساب تلگرامه، نه هر آدم.** کسی که حساب تلگرام دوم باز کنه می‌تونه یکی دیگه بگیره. چیزی که جلوش رو می‌گیره آی‌پیه: آی‌پی‌ای که برای یه حساب ثبت شده برای حساب دیگه ثبت نمیشه، پس تست دوم روی همون اینترنت به درد نمی‌خوره.
- **پلن فقط توی ربات فروخته میشه.** صفحهٔ وب رسید می‌گیره ولی پلن انتخاب نمیکنه و پرداخت آنلاین نداره؛ اپراتور بعد از تأیید اون رسید، حجم رو دستی می‌ذاره.
- **با چند رله، ربات به یکی لینک میده.** مینی‌اپ و صفحهٔ پرداخت روی رله‌ای هستن که دامنه داره و آخر از همه همگام شده.
- **مینی‌اپ روی همهٔ نسخه‌های تلگرام امتحان نشده.** اطلاعاتش رو از آدرس صفحه می‌خونه، نه از اسکریپت تلگرام که توی ایران فیلتره؛ نوشتن دستی آی‌پی توی ربات همیشه کار میکنه.
- **دانلود Xbox گیر میکنه**، چه از رله بره چه نره. اندازه‌گیری شده، حل نشده.
- **ترافیک دو برابر خرج میشه.** یه گیگابایتِ کاربر تقریبا میشه دو گیگ روی رله و دو گیگ روی خروجی — اندازه‌گیری شده، و قبل از قیمت‌گذاری ارزش دونستن داره.
